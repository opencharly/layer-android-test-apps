# 2026.251.0811 — fix(candy): F-Droid from a committed f-droid.org APK — drop the APKPure download path

## Summary

E-5 R1 fixture fix for the check-android-emulator-pod bring-up: the F-Droid install
on the `device` member switched OFF the APKPure download path.

**RCA** (root-cause-analyzer, evidence probed live 2026-09-08T00:45Z): the candy's
`apk:` list carried `package: org.fdroid.fdroid` with `source: apk-pure`, and
APKPure is behind a Cloudflare bot-wall that returns **HTTP 403** for the apkeep
download request (curl-UA probe) and a UA-sensitive 403/404 on the API
path — identically from the host AND in-pod. That made the peer `device`'s
F-Droid install the bring-up kill for the E-5 `charly check run
check-android-emulator-pod` lane (the 204s bring-up block). The canonical source
`https://f-droid.org/F-Droid.apk` returns **HTTP 200**.

**Fix** (the committed-APK pattern `layer-android-apidemos` already uses — pure
goadb push, no apkeep, no source): commit `tests/data/F-Droid.apk` (12.4 MB, the
canonical F-Droid client from f-droid.org, sha256
`985f5181d48bb6bafd54083a048b391271e0ab28385881cc41294fb01a222762`) and point the
`apk:` entry at it. No apkpure/apk-pure dependency remains anywhere. The plan
checks are unchanged (they assert the org.fdroid.fdroid package + launch after the
deploy).
